# MarkGraph 架构与技术方案（Phase 1）

> 版本：1.0 ｜ 日期：2026-08-19 ｜ 依据：`01-需求.md`

## 1. 总体架构

```
┌────────────────────────────── 浏览器 ──────────────────────────────┐
│  React SPA（Vite 构建）                                             │
│  ├── 布局壳：文件树 | 标签页(笔记/图谱) | 右栏面板插槽                │
│  ├── CodeMirror 6 编辑器（live preview + wikilink 扩展）             │
│  ├── 图谱：d3-force 布局 + canvas 渲染                               │
│  ├── zustand store（vault 树、标签页、索引缓存、主题）                │
│  └── 事件总线 + 命令 registry                                       │
└───────────────┬───────────────────────▲───────────────────────────┘
        REST /api/*（fetch）            SSE /api/events（chokidar 监听）
┌───────────────▼───────────────────────┴───────────────────────────┐
│  Fastify (Node + TS)                                                │
│  ├── vault 文件 CRUD（fs/promises，路径校验防穿越）                  │
│  ├── chokidar 监听 VAULT_DIR → SSE 广播变更                          │
│  └── 生产模式托管 dist/ 静态文件                                      │
└───────────────────────────────┬────────────────────────────────────┘
                                ▼
                     本地文件夹 vault（纯 .md，任何编辑器可直接打开）
```

- **部署形态**：MarkGraph 是**服务器端应用**，浏览器只做客户端。本机开发用 `npm run dev`（Vite + Fastify）；生产用 `npm run build && npm start`，默认监听 `127.0.0.1`。未来演进：多端原生 App 作为同一服务端 API 的客户端。
- **环境变量**：`HOST`（默认 127.0.0.1；反向代理后可设 0.0.0.0，无鉴权，勿暴露公网）、`PORT`（默认 7710）、`VAULT_DIR`（笔记库文件夹，仓库外，不入 git）

## 2. 技术选型与理由

| 层 | 选择 | 理由 |
|---|---|---|
| 前端框架 | React 18 + TypeScript + Vite | CM6 生态封装（@uiw/react-codemirror）成熟；TS 保证索引/状态代码可维护 |
| 样式 | Tailwind CSS + shadcn/ui | 组件复制进仓库非黑盒依赖；命令面板/菜单/对话框用 Radix 底座获得键盘导航与无障碍；主题经 CSS 变量 token 全量可控 |
| 编辑器 | CodeMirror 6 | Markdown 生态成熟，live preview 与 wikilink decoration 可自行扩展 |
| 图谱 | d3-force + 原生 canvas | 力导向布局标准库；canvas 渲染保证千节点流畅；不引图表库 |
| 状态 | zustand | 轻、无样板代码，适合中型单页应用 |
| 后端 | Fastify + tsx | SSE / 静态托管 / 路由一体，开发时用 tsx 热重载 |
| 文件监听 | chokidar | 跨平台文件变更监听事实标准 |

**明确不引入**：MUI/Antd（强视觉组件库与多主题方案冲突）、Electron/Tauri（目标是网页版）、数据库（纯文件存储）。

## 4. API 契约

所有响应 JSON；错误统一 `{ error: string }` + 4xx/5xx。路径参数为 vault 内相对 POSIX 路径（如 `笔记/项目/读书.md`）。

| 方法 | 路径 | 请求 | 成功响应 | 说明 |
|---|---|---|---|---|
| GET | `/api/tree` | — | `{ tree: VaultNode }` | VaultNode = `{ type:"dir"\|"file", name, path, children? }`，按名称排序，隐藏项已滤除 |
| GET | `/api/note?path=` | — | `{ content: string, mtime: number }` | 仅接受 `.md` |
| GET | `/api/notes` | — | `{ notes: { path, content }[] }` | 全部笔记内容（前端索引器全量构建；只读） |
| PUT | `/api/note` | `{ path, content }` | `{ mtime: number }` | 保存笔记 |
| POST | `/api/note/create` | `{ path, isDir? }` | `{ path }` | 新建笔记或文件夹；重名返回 409 |
| POST | `/api/note/rename` | `{ from, to }` | `{ path }` | 移动/重命名 |
| POST | `/api/note/delete` | `{ path }` | `{ ok: true }` | 递归删除（前端负责二次确认） |
| GET | `/api/events` | — | SSE `text/event-stream` | 事件 `change`/`add`/`unlink`，data 为 `{ path, kind }` |

**安全规则**：所有 path 经 `path.resolve(vaultDir, p)`，结果必须以 `vaultDir + sep` 开头，否则 400；写操作仅允许 `.md` 后缀（rename 除外，允许目录）。

## 5. 前端数据流与索引

1. 启动：`GET /api/tree` → store.tree；订阅 SSE
2. 打开笔记：`GET /api/note` → store.openTabs；编辑防抖 1.5s → `PUT /api/note` → 事件总线 `note:save`
3. **索引器（indexer.ts）**：输入「全部笔记路径+内容」的 Map，输出：
   - `nodes: { path, name, folder }[]`
   - `edges: { source, target, resolved }[]`（resolved=目标存在；断链目标生成幽灵节点）
   - `backlinks: Map<path, { from, context }[]>`（context=引用行去 markdown 语法后的摘录）
   - `tags: Map<tag, paths[]>`
   - 解析正则与 CM6 高亮共用 `wikilink.ts` 中同一套规则，保证一致
4. 索引重建时机：启动后首次全量；之后任一 `note:save`/`tree:change` 事件触发增量重算（全量重算在 500 篇规模下 <100ms，MVP 直接全量，不做脏标记优化）
5. 图谱从索引构图；反链面板、`[[` 补全（候选=nodes）、断链检测（edges.resolved）同源取数

## 6. 主题 token 体系

- `src/styles/app.css` 用 `[data-theme="…"]` 定义五套 CSS 变量（内部 id：`apple` / `paper` / `obsidian` / `x` / `meta`，对外显示名：玻璃 / 纸感 / 经典深色 / 纯黑 / 卡片）
- `<html data-theme="apple|paper|obsidian|x|meta">` 切换；默认 `apple`
- 组件样式只引用变量，禁止硬编码颜色（保证 F6.3 单一 DOM 多主题）
